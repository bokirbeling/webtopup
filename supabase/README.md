# Supabase Local Scaffold & Migration Workflow

This project uses the Supabase CLI with a localhost-first workflow. Keep commands non-destructive by default and avoid reset-first flows.

## 1) CLI discovery and health checks

Run these commands from repository root:

```bash
supabase --version
supabase --help
supabase db --help
supabase migration --help
supabase migration new --help
```

## 2) Local scaffold

- `supabase/config.toml` is generated by `supabase init`.
- Keep credentials out of tracked files; use environment variables.

## 3) Migration command flow (Task 3 readiness)

Create a migration file (empty scaffold first):

```bash
supabase migration new <descriptive_migration_name>
```

After creating/editing migration SQL, inspect available migration commands and local state:

```bash
supabase migration --help
supabase migration list --help
supabase db --help
```

When schema work starts (Task 4+), follow this safe sequence:

1. Create migration file with `supabase migration new ...`
2. Add SQL changes into `supabase/migrations/*.sql`
3. Use CLI help/discovery before execution (`--help`)
4. Verify with lint/typecheck/tests in backend after config changes

## 4) Required backend env keys for Supabase binding

Backend config now requires:

- `NODE_ENV`
- `PORT`
- `SUPABASE_URL` (must be valid `http://` or `https://` URL)
- `SUPABASE_SERVICE_ROLE_KEY` (non-empty)

Missing/invalid values fail fast with clear `[config] ...` startup errors.
